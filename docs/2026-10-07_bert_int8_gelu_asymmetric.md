# BERT int8 — GELU 출력 비대칭 양자화 (2026-10-07)

FC1·FC2 per-channel 까지 끝난 모델(NPU 0.9503, work log `docs/2026-09-29_int8_accuracy_work_log.md` §7.7)에서
남은 오차가 어디서 오는지 연산별로 재고, 가장 큰 원인인 GELU 출력(FC2 입력)의 양자화를 비대칭으로 바꿨다.
컴파일러에는 "활성값 zero-point 가 0 이 아닌 per-channel matmul" 을 받는 일반 기능을 넣었다.

---

## 0. 요약

| | FC1+FC2 per-channel (지금) | + GELU 출력 비대칭 |
|---|---:|---:|
| ORT, 64 문장 (fp32 대비 corr) | 0.9509 | 0.9697 |
| **NPU, 64 문장** | **0.9503** (최저 0.9422) | **0.9690** (최저 0.9624) |
| NPU − ORT | −0.0006 | −0.0007 |
| 1 회 추론 (중앙값, 2 회 측정) | 329 / 329 ms | 332 / 332 ms |

- NPU 에서 **+0.0187**, 64 문장 **전부** 좋아졌다.
- 남은 오차의 절반 이상이 GELU 출력 한 곳이었다(§1). 이 값은 음수 쪽이 −0.3 ~ −0.7 에서 끝나는데
  대칭 int8 이라 격자의 절반 가까이를 버리고 있었다(§2).
- 컴파일러 변경은 기존 패스 두 개에 경우 하나씩을 더한 것이다(§4). zero-point 가 0 인 기존 모델의
  vmfb 는 HEAD 컴파일러로 만든 것과 **바이트 동일**하다(§6).

## 1. 남은 오차는 어디서 오나 — 연산별 leave-one-out

**기준 모델.** 배포 ONNX(`/tmp/pcfold/mix/bertx_int8.onnx`)를 ORT 로 그대로 돌리면 0.7871 이다. NPU 는
attn_out 과 FC2 출력을 int16 으로 넓혀 쓰는데(③, 컴파일러 기본값) ONNX 에는 int8 로 남아 있기 때문이다.
그래서 두 출력에 int16 가짜 양자화를 넣은 모델(`quant/fc2_int16.py` 를 두 곳에 적용, 0.9509 = NPU 0.9503
과 일치)을 기준으로 했다.

**방법.** 한 종류의 Q/DQ 를 빼서 fp32 로 되돌리고 corr 상승을 본다. ORT, 평가 64 문장.

| fp32 로 되돌린 것 | corr | 기준 대비 |
|---|---:|---:|
| 없음 (기준) | 0.9509 | — |
| **GELU 출력 (FC2 입력)** | **0.9783** | **+0.0274** |
| FC1 출력 (GELU 입력) | 0.9580 | +0.0071 |
| LN 출력 (embedding / FFN 뒤) | 0.9545 | +0.0036 |
| softmax 출력 | 0.9537 | +0.0028 |
| LN 출력 (attention 뒤) | 0.9535 | +0.0026 |
| Q/K/V 헤드, QKᵀ, AV, attn_out(int16), FC2 출력(int16) | 0.9505 ~ 0.9513 | ±0.0004 이내 |
| 가중치 (QKV / attn_out / FC1 / FC2 / 전부) | 0.9506 ~ 0.9510 | 0 |
| activation 전부 | 0.9991 | +0.0482 |

- 가중치 오차는 per-channel 로 다 없어졌다. 남은 것은 전부 activation 이다.
- 어텐션 쪽 matmul(QKᵀ, AV)은 거의 기여하지 않는다.
- 한 종류씩의 이득 합(약 +0.045)이 전체(+0.048)와 비슷하다.

## 2. GELU 출력의 값 범위와 int8 격자

GELU 출력은 SmoothQuant 로 `x / s` 가 된 FC2 입력이다(`sq_x_N`). 12 층 모두 **대칭 int8, zero-point 0**.
평가 16 문장에서 본 값 범위:

| 층 | 값 범위 | int8 격자 | 격자 사용 비율 |
|---|---|---|---:|
| 0 | −0.54 ~ 10.90 | −2.18 ~ 2.16 | (위쪽 잘림) |
| 1 | −0.79 ~ 2.85 | −2.76 ~ 2.74 | 0.66 |
| 2 | −0.50 ~ 7.40 | −7.41 ~ 7.36 | 0.53 |
| 5 | −0.71 ~ 5.38 | −4.98 ~ 4.94 | 0.61 |
| 6 | −0.49 ~ 6.52 | −4.09 ~ 4.06 | (위쪽 잘림) |
| 9 | −0.45 ~ 7.62 | −7.46 ~ 7.41 | 0.54 |
| 10 | −0.37 ~ 12.32 | −12.42 ~ 12.32 | 0.51 |
| 11 | −0.30 ~ 1.97 | −1.58 ~ 1.56 | 0.72 |

- 값의 89 ~ 95 % 가 음수(0 근처의 작은 음수)인데, 격자 간격이 0.012 ~ 0.097 이다.
- 위쪽 잘림은 보정이 백분위(99.999)이기 때문이고, 기존 기록에서 더 낮은 백분위·entropy 는 나빴다. 손대지 않았다.

## 3. ORT 실험 — 비대칭으로

위쪽 끝(`127 · scale`, 지금 값)은 그대로 두고 아래쪽 끝을 보정 문장의 최솟값으로 잡아 [lo, hi] 를 256 칸에 나눴다.
GELU 출력 12 곳만 바꿨다. bias 접기 열은 float 에서 원래 값으로 붙였다(이 실험만 해당).

| | corr | 최저 |
|---|---:|---:|
| 대칭 (같은 계산 경로) | 0.9516 | 0.9397 |
| **비대칭** | **0.9696** | **0.9620** |
| 참고: GELU 출력 fp32 | 0.9783 | 0.9725 |

층마다 scale 이 1.57 ~ 1.95 배 작아졌고 zero-point 는 −72 ~ −121 이다. GELU 출력 fp32 이득의 약 2/3 를 얻는다.

## 4. 컴파일러 변경

### 4.1 막혀 있던 곳

per-tensor matmul 은 ONNX importer 가 `linalg.quantized_matmul` 로 내려 upstream 에서 zero-point 가 처리된다.
per-channel 가중치는 그 named op 에 실리지 못해 float matmul 로 오고, `AMDAIEFoldPerChannelDequantIntoMatmul` 가
int8 matmul 로 되돌린다. 이 패스가 **"zero-point 는 상수 0 이어야 한다"** 며 거부했다. bias 접기 스크립트도 같은
이유로 거부했다.

### 4.2 수식

활성값 zero-point `zx`, 가중치 `w[k,n]`(zero-point 0) 에 대해

```
Σ_k (x[m,k] − zx) · w[k,n] = acc[m,n] − zx · Σ_k w[k,n]
```

둘째 항은 활성값과 무관하다. 가중치가 상수면 `c[n] = zx · Σ_k w[k,n]` 은 컴파일 시간에 계산되는 [N] 표다.

### 4.3 바꾼 것

| 파일 | 변경 |
|---|---|
| `Transforms/AMDAIEFoldPerChannelDequantIntoMatmul.cpp` | 활성값 dequant `sitofp(extsi(x) − zx) · s` 에서 스칼라 상수 `zx` 를 받는다. 가중치 상수(dense 또는 dense_resource)에서 열 합을 읽어 `c[n]` 을 만들고, 꼬리를 `sitofp(acc − c[n]) · (sx·sw[n])` 로 만든다. 가중치 zero-point 가 0 이 아니면(실행 중 활성값 행 합이 필요) 그대로 거부한다. `c[n]` 이 i32 를 넘으면 거부한다 |
| `Transforms/AMDAIEPerChannelIntegerRequantization.cpp` | 꼬리에 세 번째 입력 `c : [N] i32` 와 `subi` 가 있으면 받아서 `round_half_even((acc − c[n]) · m[n] >> shift)` 로 바꾼다. `c` 는 `m` 과 같이 코어 지역 상수 표가 된다 |
| `Transforms/Passes.td` | 두 패스 설명에 위 형태를 추가 |

**보정을 꼬리에 둔 이유.**
- 누산기 초기값을 `−c[n]` 로 채우는 방법은 matmul 이 C 를 메모리에서 읽게 만들어 세 번째 입력 스트림이 생긴다.
  npu4 의 shim MM2S 는 2 채널이다.
- 모델 쪽 bias 접기 행에 넣는 방법은 `c[n]` 이 10⁵ 단위라 int8 행이 크게 늘어난다.

둘 다 ONNX QDQ 의 표준 필드(zero-point)를 처리하는 일반 기능이고, 모델 이름이나 BERT 구조를 보지 않는다.

## 5. 모델 준비

wjjang 원본 스크립트는 건드리지 않았다. 새로 만든 것은 스크래치의 `asym/` 아래에 있다.

| 단계 | 스크립트 | 비고 |
|---|---|---|
| per-channel 끼우기 | `pcfold/splice_mix.py` (기존) | FC1, FC2 |
| **GELU 출력 비대칭** | `asym/asym_q.py` (새) | `sq_x_N` 12 곳. hi = 지금 `127·scale`, lo = fp32 SmoothQuant 모델(`/tmp/pc/s.onnx`)의 보정 90 문장 최솟값 |
| bias 접기 | `asym/fold_bias_into_k_general_pcz.py` (per-channel 복사본의 복사본) | 활성값 zero-point 를 받는다. 덧붙이는 열에 `v + zx` 를 저장해 `(x_q − zx) = v` 가 되게 한다. 컴파일러의 `c[n]` 이 bias 행까지 포함하므로 수식이 그대로 맞는다 |
| 나머지 | `fold_bias_into_k.py`, `fold_shape_consts.py`, `head_split.py`, `hoist_kfold_pad.py` (원본) | `hoist_kfold_pad.py` 는 int8 Pad 를 구조만 옮기므로 zero-point 와 무관 |

## 6. 검증

| 확인 | 결과 |
|---|---|
| 재현체 2D matmul (32×64 · 64×64, zx = −111, per-channel) NPU vs ORT | **2048/2048 동일** |
| 재현체 FC2 모양 batch matmul (1×32×3136 · 3136×64) NPU vs ORT | **2048/2048 동일** |
| 새 bias 접기 복사본을 대칭 모델에 | 기존 배포 모델과 **md5 동일** |
| 대칭 배포 모델: 수정 컴파일러 vs HEAD 컴파일러 vmfb | **바이트 동일** |
| 비대칭 배포 모델 컴파일 | 오류·program memory 초과 없음 |
| 최종 소스(주석·설명 정리 후)로 다시 컴파일 | 측정에 쓴 비대칭 vmfb 와 바이트 동일 |
| NPU 64 문장 | 0.9690 (최저 0.9624), ORT 0.9697 과 −0.0007 (−1.9 SE), 64/64 개선 |

재현체 2D 는 가중치(4 KB)가 인라인 상수 기준(16 KB)보다 작아 디스패치 안에 박히면서 컴파일이 실패했다.
이번 변경과는 별개이고, 기준을 2 KB 로 낮춰 확인했다. FC2 모양 재현체와 BERT 는 기본값으로 컴파일된다.
